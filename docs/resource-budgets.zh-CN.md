# 资源与保留预算

[English](resource-budgets.md) | 简体中文

Parade 面向小型 Linux VPS 和大规模 Fleet，但不会宣称零资源占用或数据库永不
增长。普通遥测、队列和运维历史都有明确边界；低频的身份、审计、墓碑、安全发现
和计费证据因安全要求而持久保留。

## 默认采样与上报

- 每 10 秒在本机采样资源计数器；
- 大约每 5 分钟带随机抖动上传紧凑汇总；
- 只保留一个待发 Agent 报告，并使用有界退避/重试；
- 普通紧凑报告只包含很小的 OS/kernel/architecture 标识及内容哈希；
- 进程/监听信息只在变化或可疑时发送有界结果；
- 有界进程/socket 快照只用于有类型、会过期的只读观察租约；
- live detail 最长 10 分钟自动结束。

正常上行目标低于每 Agent 每 30 天 10 MiB；确定性测试超过 20 MiB 会失败。
显式 live-detail 和真实安全事件突发不计入正常预算。不能为节省字节削弱正确性、
认证或计费。

## 当前实测基线

2026年08月08日成功的本机 Release 基线：

| 测量项 | 结果 |
| --- | ---: |
| 普通编码报告正文 | 390 B |
| 合成的 32 进程快照正文 | 3,469 B |
| 每 Agent 每 30 天正常估算 | 5,695,110 B（5.431 MiB） |
| Agent Release 二进制 | 2,947,936 B |
| Hub Release 二进制 | 6,302,600 B |
| Hub 空闲峰值 RSS | 8,612 KiB |
| Hub 空闲文件描述符 / 线程 | 7 / 5 |
| 1,000 份签名报告写入 | 13.681 秒（73.1 份/秒） |
| 1,000 Agent 数量查询 | 4.266 ms |
| 合成数据库大小 | 1,822,720 B |

测试机使用 `powersave` governor，`perf_event_paranoid=3`。这些是可复现的回归
数据，不是对所有硬件的容量承诺。协议开销假设包含每请求 250 字节、每天 2,048
TLS 字节，并保守预留相当于每天一份 32 进程快照的字节。Agent 没有每日快照
调度；稳定进程证据变化或 typed lease 请求时才发送进程证据，因此真实进程/
监听变化和事件会按实际活动增加流量。精确命令与原始台账见
[`PLANS.md`](../PLANS.md)。

## Agent 硬边界

- 随附 unit 设置 `MemoryHigh=96M`、`MemoryMax=128M`、`TasksMax=64`；
- 一个待发报告；
- 最多 64 个上报接口、32 个流量异常；
- 最多 256 个同启动周期接口基线；
- 单个 procfs 文件最多读取 1 MiB；
- 有界 Top-N 进程和监听快照；
- 正常计数器状态最多每分钟持久化一次。

boot 变化、counter reset/新段、待发报告、ACK、身份和策略变化仍然立即落盘。
一分钟稳态 checkpoint 降低磁盘写放大，同时避免第二次崩溃把整个新计数段重复
算成新流量。

## Hub 硬边界

- 随附 unit 设置 `MemoryHigh=256M`、`MemoryMax=512M`、`TasksMax=128`；
- 报告正文最大 256 KiB；
- 有界限流键、15 秒 HTTP handler timeout、查询分页和 UI 行数；
- SQLite WAL、自动 checkpoint 和 16 MiB journal 上限；
- 每表每次保留事务最多清理 10,000 条过期记录；
- 上报拓扑最多返回 24 条边；
- 每个 server/rule/version 最多 32 条发现主体序列加一条 overflow。

systemd 上限是安全默认值。只有实测真实 Fleet 后才提高 Hub 限额，并记录本地
override。Parade 不修改全机 journald 配额。

## 保留窗口

| 数据 | 默认保留 |
| --- | --- |
| 详细资源汇总 | 30 天 |
| 流量汇总 | 90 天 |
| 进程/监听变化 | 7 天加最新值 |
| 事件 | 180 天 |
| 普通消息元数据 | 1 天 |
| 原始流量检查点 | 400 天，并保留种子绑定/最新检查点 |
| 过期 session/token/lease | 周期性有界清理 |

Agent 身份/撤销、永久墓碑、审计、安全发现历史、计费周期、不可变种子和追加修正
不会常规删除，否则会削弱安全或计费。无限次真实操作仍会造成缓慢且合理的数据库
增长。应按政策备份/归档并监控 `/var/lib/parade`，不能宣传“绝对零增长”。

## 运行回归门禁

只能在隔离开发机或 CI 上运行，不能在被监测主机上执行：

```bash
PARADE_PERF_REPORT=/tmp/parade-performance.txt scripts/performance-gate.sh
```

门禁构建锁定依赖的正常 Release 二进制，记录 Git/二进制/机器元数据，检查体积与
依赖上限，执行确定性带宽和 1,000 Agent 测试，并采样空闲 Hub。它不会控制、
压测、kill、重新配置或向被监测 VPS 注入故障。

资源增长诊断见[故障排查](troubleshooting.zh-CN.md)。
