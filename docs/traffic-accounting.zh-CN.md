# 厂商流量人工计费

[English](traffic-accounting.md) | 简体中文

当前里程碑明确不接入厂商 API。操作员把厂商面板的本周期当前用量输入一次，
Parade 将它绑定到精确 Agent 检查点，再增加之后本机观察到的流量。

```text
检查点上的不可变厂商种子
+ 检查点后选中接口的流量
+ 仅追加、可审计的修正
= 当前周期用量
```

Linux 计数器不能重建开始观察前的流量。Parade 会保留这个限制，不会静默猜数。

## 五种闭合计费模式

| 模式 | 厂商种子 | Parade 结果 | 限额 |
| --- | --- | --- | --- |
| 入站 + 出站 | 一个合计值 | 种子 + 后续 RX + 后续 TX | 一个总限额 |
| 仅入站 | 入站值 | 入站种子 + 后续 RX | 一个入站限额 |
| 仅出站 | 出站值 | 出站种子 + 后续 TX | 一个出站限额 |
| 较大方向 | 同时输入入站和出站 | `max(当前 RX, 当前 TX)` | 一个总限额 |
| 分别计费 | 同时输入入站和出站 | RX/TX 两个独立总量 | RX/TX 独立限额 |

“较大方向”和“分别计费”会拒绝只有合计值的种子。例如 RX 从 100 开始、TX 从
90 开始，之后 TX 增加 20，正确的较大方向结果是 110；把合计种子只加较大增量
会错误得到 120。

计费模式是有版本的闭合枚举，不接受自定义公式、脚本、厂商代码、SQL、路径、
命令或插件。

## 配置主机

第一次保存种子前设置：

- IANA 时区，例如 `Asia/Shanghai`；
- 1–31 的账期日期；
- 当地边界时间；
- 计费模式与可选限额；
- 自动或显式接口选择策略。

日期 29–31 在短月取最后一天；夏令时缺口和歧义按配置时区确定处理。已有种子
历史后，时区、锚点和计费模式会冻结，避免重解释旧周期；接口策略和限额仍可
修改并进入审计。

自动接口选择读取 IPv4 和 IPv6 默认路由，并排除 loopback、bridge、veth/
container 与 tunnel 类设备。界面显示 Agent 实际选择的接口、异常以及 partial/
estimated 原因。若厂商口径不同，应使用显式 allowlist。

## 记录本周期种子

1. 等待首个可靠签名检查点；
2. 大致同时查看厂商面板；
3. 输入本周期值、单位和有意义的来源说明；
4. 核对精确检查点、生效时间、周期和公式预览；
5. 只确认一次。

每周期只接受一个不可变主种子。记录包含操作员、创建/生效时间、来源说明和检查
点。之后发现输入错误时不能修改种子，应使用追加修正。

## 修正数值

添加带原因的正值或负值调整。修正是仅追加的审计记录；已有种子和修正永不原地
编辑。分别计费模式还必须选择方向。保存后检查组件分解和 Audit。

## 自动月结

到达配置的当地边界后，Hub 创建种子为零的新周期。它不会写入、重置、绕回或
以任何方式修改 Linux 计数器；已关闭周期继续保留。

若边界前后都有可信检查点，Parade 可以细化拆分。若 Agent 离线，或者 counter
reset、重启、改名使拆分不可能，受影响区间会继续显示 `estimated` 或 `partial`。
操作员可以事后追加厂商修正，但 Parade 不会把不确定的本地证据静默升级成精确。

## 理解与厂商的差异

厂商用量可能包含链路层开销、舍入、私网流量、虚拟交换流量、方向权重、共享
NAT 网关或其他 Linux 接口计数器无法复现的策略。共享 NAT 下，一台 Agent 无法
把其他主机流量归属给自己。

因此 Traffic 页面明确展示：

- 厂商种子与来源说明；
- 种子检查点和生效时间；
- 实际选中接口与观察到的 RX/TX 组成；
- 每一条修正和操作员；
- 周期边界与关闭历史；
- 置信度、异常、缺口与明确不确定性。

Parade 是透明对账台账，不是厂商计费系统的替代品。
